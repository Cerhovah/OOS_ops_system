# PLAN

## 운영 규칙

- 구현 전에 이 문서를 갱신하고 모든 작업을 `SPEC.md`의 수용 기준(AC)에 연결한다.
- 한 번에 한 Phase만 진행하며 §10.3 게이트 통과 전 다음 Phase로 넘어가지 않는다.
- §10.4 정지 조건이 생기면 해당 작업을 멈추고 `QUESTIONS.md`에 기록한다. 독립 작업만 계속한다.
- 기술 내부 결정은 `DECISIONS.md`, 사용자에게 의미 있는 변경은 `CHANGELOG.md`, 범위 밖 제안은 `FUTURE.md`에 기록한다.
- 완료 판정에는 구현, 자동 테스트, 수동·실기기 검증, 증빙, 문서 갱신이 모두 필요하다.
- Phase 1 검증 중에는 기존 개발 APK와 Metro tunnel을 우선 재사용하며, 검증에 필요하지 않은 재빌드·재설치·환경 변경은 하지 않는다.

## 현재 상태

- 단계: Phase 1 — 초안(v0.1)
- 상태: **구현·자동 게이트·Android 실기기 게이트 통과 · 최종 체크포인트 커밋 전**
- 문서 기준일: 2026-08-24
- 목표: AC-1~AC-18 전부 통과, §10.3 게이트 통과, 사용자 기기에서 하루치 실제 기록 완료
- 구현 기준: `ced67ac` (`v0.1-phase1`)에 Expo/React Native 앱, SQLite 마이그레이션·시드, Phase 1 화면·알림·내보내기와 자동 테스트가 존재한다.
- 검증 기준: TypeScript, ESLint, 40개 자동 테스트, 도메인 커버리지, 의존성 검사, Android JS bundle이 통과했다. 실제 SQLite migration/repository와 Android 알림·딥링크·파일 공유 경로도 자동 검증에 포함했다.
- 현재 진단: 버튼식 시각 선택·30초 독립 테스트·명시적 열기 동작과 `daily-records-v2` 채널을 적용했다. 사용자가 잠금화면 알림 수신·동작과 비행기 모드 기록·재시작 보존까지 실기기에서 확인했다.
- 범위 제한: Phase 2의 프로젝트·인증·초기 업로드·충돌 정책은 결정됐지만 구현은 시작하지 않았다.

## Phase 2 승인된 착수 계획 — 미구현

1. **보호 체크포인트:** Phase 1 후속 수정 커밋·푸시, 휴대폰 SQLite 전체 JSON/CSV 백업, 원격 프로젝트가 비어 있음을 확인한다.
2. **프로젝트·스키마:** 사용자가 전용 무료 Supabase 프로젝트를 가능한 경우 Seoul 리전에 만들면, SQLite 미러 테이블에 `user_id`, outbox 수신, tombstone, 충돌 로그와 서버 동기화 버전을 설계한다.
3. **인증·RLS:** 최초 이메일 계정만 생성하고 6자리 OTP 세션을 유지한다. 이후 신규 가입은 서버 설정과 클라이언트 요청 모두에서 차단하며, 모든 공개 테이블에 본인 행만 허용하는 RLS를 적용하고 다른 사용자 접근 실패를 시험한다.
4. **AC-19 최초 업로드·복구:** 현재 휴대폰 SQLite의 모든 행·삭제 묘비·계획 버전을 멱등하게 업로드하고 행 수·ID·버전을 대조한다. 원본은 삭제하지 않으며 별도 시험 데이터로 재설치 복구를 검증한다.
5. **AC-20 오프라인 동기화:** 로컬 쓰기는 즉시 SQLite와 outbox에 남기고, 온라인 복귀 시 자동 전송한다. 서버 버전·시각 우선 LWW와 결정적 동률 해소를 적용하고 승자·패자를 모두 충돌 로그에 보존한다.
6. **AC-21 동기화 UI:** 설정에 로그인 상태, 마지막 성공 시각, 진행·오류 상태, `지금 동기화`, 충돌 로그 열람을 추가한다.
7. **AC-22 보안·게이트:** RLS·재로그인·중복 전송·중단 재개·오프라인 회귀·복구·데이터 손실 0을 자동/실기기로 검증한 뒤 Phase 2 게이트를 판정한다.
