# OOS Ops — Phase 5 디자인 레퍼런스 결정

조사일: 2026-09-06 · 적용 규범: [SPEC](SPEC.md) §17~§18

## 최종 주 레퍼런스 결정

Mobbin의 **[Tiimo — Completing a task](https://mobbin.com/flows/ea7537d2-b745-4764-ab22-dcf5c71b444f)** 5화면 flow를 P5의 유일한 주 레퍼런스로 확정한다. 날짜별 목록에서 `Start now`로 항목을 시작하고, 실행 중 남은 시간과 작업 맥락을 유지하며, 완료 상태로 닫는 흐름이 OOS의 `오늘 → 선택/시작 → 실행 → 종료`와 가장 가깝다.

OOS의 시각 번역 이름은 **Quiet Routine**이다. Tiimo에서 채택하는 것은 날짜가 먼저 보이는 목록, 행 안의 명시적 시작 상태, 실행 중에도 항목 맥락이 사라지지 않는 구조, 완료 후 목록으로 자연스럽게 돌아오는 전환이다. 보라색 면 카드, 온보딩 배너, 체크리스트/하위 작업, 진행률 링, 축하 문구, 4탭, 떠 있는 추가 버튼은 배제한다. OOS는 중립 배경·평면 행·한 개의 강조색·큰 시간 숫자·한 화면 한 주요 행동·오늘/기록 2탭으로 다시 설계한다.

TIDE `Starting focus timer`는 가장 조용하고 유려했지만 소리/집중 타이머 중심이라 오늘 할일 선택과 루틴 완료가 약했다. Opal `Completing a scheduled session`은 연속 실행은 분명하지만 앱 차단·점수·강한 사진/그래픽이 OOS의 중립 기록기 불변조건과 충돌했다. 따라서 둘은 채택 요소를 섞는 보조 디자인 소스가 아니라 **Tiimo 선택을 검증한 비교 후보**로만 남긴다.

기존 Flow·Structured·Toggl 공개 자료는 기능 누락을 발견하는 역사적 예비 조사로만 유지한다. P5의 화면 배치를 여러 앱의 장점 조합으로 결정하지 않는다.

앱의 첫 질문은 `오늘 어떤 일을 할까요?` 하나다. 저장된 항목을 고르면 시작되고, 화면을 끄면 된다. P5 실행 중에는 항목명·경과 시간·종료가 중심이고, 합계와 과거 기록은 `기록` 탭에서 본다. 남은/초과 시간과 일시정지·재개는 P6에서만 추가한다.

## 조사 방식과 한계

공식 제품 사이트·도움말·디자인팀 글을 외부 검색하고 열람했다. Structured 도움말의 **당일 목록 → 항목 상세 → 전체 타이머** 실제 3화면 이미지를 브라우저로 보았고, Flow 공식 소개의 타이머/통계 화면을 시각 확인했다. Toss 공식 글에서 긴 이름·스크롤·큰 글씨·포커스 규칙을 확인했다. 제품을 설치해 조작한 검증은 아니다.

2026-09-06 확인 결과 Figma MCP와 Mobbin ChatGPT 플러그인은 모두 설치돼 있다. Mobbin 권한 화면에는 `Allow low-risk actions`가 표시되지만 현재 Codex 작업에는 Mobbin 전용 callable 도구가 노출되지 않았다. 따라서 이미 확인한 Tiimo flow를 기준으로 고정하고, 미노출을 이유로 P5에 runtime dependency나 별도 웹 연동을 넣지 않았다.

Figma Starter의 일반 MCP 쓰기 한도에서는 첫 화면 이후 추가 편집이 차단됐다. 추가 결제 없이, 동일한 앱 토큰과 합성 데이터만 사용한 로컬 4화면을 Figma의 HTML capture 경로로 전송해 `Today idle`, `Task sheet`, `Timer running`, `Records ledger`를 완성했다. 캡처용 임시 HTML은 전송 직후 제거했으며 앱 runtime에는 포함되지 않는다. 이 산출물과 Tiimo의 정보 위계를 대조해 코드의 간격·타이포·행 밀도·버튼 위계를 확정했다.

Figma 4화면: [OOS Ops — Phase 5 Reference UI · node 13:2](https://www.figma.com/design/Be9DsWkov1vg3ptUFPpj6F?node-id=13-2)

Wise의 구 `components/bottom-sheet`, `components/list-item` 주소는 텍스트 수집에서 JS 안내, 브라우저에서 404였다. 따라서 해당 컴포넌트의 세부 배치를 확인했다고 주장하지 않는다. 공식 [Wise Design](https://wise.design/) 홈은 열렸지만 금융 원장 화면을 입증하지 못해 최종 기준에서 제외했다.

## 선택한 패턴 → OOS 규칙

| 영역 | 채택한 패턴 | OOS에서 고정하는 규칙 | 배제 |
|---|---|---|---|
| 할일 | Structured의 항목 기반 실행, Toss의 긴 목록 처리 | `오늘의 할일 확인` 버튼 + 자동 슬라이드. 항목명/계획 시간, 행 전체 탭. 데이터가 많아도 삭제·잘림 없이 스크롤 | 항목 상세를 거친 시작, 격려·광고·색 태그 |

자동으로 뜨는 시트·정확히 2탭·계획/실제/차이 3열은 **OOS 자체 설계**다. 위 제품이 동일 조합을 제공한다고 주장하지 않는다.

## 명세·현재 코드 충돌 감사

| 항목 | 판정 | P5에서의 처리 |
|---|---|---|
| Tiimo의 countdown·pause·restart | P6 기능과 충돌 | Figma에서는 P6 화면으로만 주석 처리. P5 코드는 경과 시간+정지만 유지 |
| Tiimo의 checklist/하위 작업·진행률 | 명세 밖 기능 | 구현하지 않음. 기존 item/entry 모델을 확장하지 않음 |
| Tiimo의 4탭·FAB·온보딩 카드 | OOS 2탭·미니멀 원칙과 충돌 | 오늘/기록 2탭, 더보기 텍스트 진입, 평면 행으로 번역 |
| iOS 제스처·sheet | Android 기준과 직접 호환되지 않음 | 정보 위계만 참고하고 Android back·키보드·200% 글씨를 별도 검증 |
| 현재 탭 header의 상단 `설정`과 기록의 `더보기` | 동일 진입 중복 | 상단 설정을 제거하고 기록 > 더보기만 유지 |
| 현재 TaskSheet 행의 계정명 | §17.3의 항목명+계획 시간보다 정보가 많음 | 기본 행에서는 제거. 빠른 생성/편집에서만 계정 선택 유지 |
| 과거 날짜 화면의 `직접 기록`·`오늘 종료` | P5의 기록 귀속 날짜 고정과 충돌 | 과거 날짜에서는 숨기거나 `오늘로 이동`으로 교체 |
| 현재 theme의 다수 semantic 색 | 4개 중립 기본색 규칙과 혼동 가능 | neutral 4역할+주 강조 1개를 주 화면에 사용하고 warning/danger는 오류·삭제에만 제한 |
| 자동 TaskSheet와 인증/알림 딥링크 | 시작 화면이 목적지를 가릴 위험 | 명시적 딥링크가 우선이라는 기존 SPEC 유지, 실기기 게이트에 포함 |

`루틴 앱`은 이 문서에서 **매일 할 항목을 선택·실행·기록하는 앱**을 뜻한다. 여러 단계를 자동으로 연속 재생하는 routine-chain 엔진, 하위 체크리스트, 연속 달성/보상 기능은 P5·P6 범위가 아니며 이번 디자인 결정으로 추가하지 않는다.

## 디자인 토큰과 접근성

- 라이트/다크 각각 background, foreground, muted, surface **4개의 중립 기본색**. 배경/텍스트/선택 상태는 명도·굵기·문자로 구분. 반투명 backdrop은 foreground+opacity 토큰으로만 파생한다. 렌더링 픽셀의 색 종류를 4로 제한한다는 뜻이 아니다.
- 서체는 Phase 5 기본 **OS 시스템 한글 서체 한 계열**, 숫자는 tabular figures. Pretendard는 필수가 아니다. 자체 폰트로 바꾸려면 오프라인 번들·라이선스·큰 글씨를 함께 검증한다.
- 크기 역할: caption 13, body 16, title 24, heading 30, timer 64; OS 글꼴 배율 적용. 역할 수를 맞추려고 긴 이름/버튼/숫자를 잘라내지 않는다.
- 간격 토큰 4/8/12/16/24/32/48, radius 0/12/16/24/pill, hit target 최소 48dp, 본문 명암비 4.5:1, 큰 글씨·컨트롤 3:1 이상을 검증값으로 확인한다.
- 탭은 텍스트 두 개. 아이콘이 없어도 뜻이 분명해야 한다. OS 필수 아이콘은 허용한다. 저장 확인·시트 전환 외 장식 애니메이션은 두지 않는다. Reduce Motion에서는 즉시 전환한다.
- 기본 글씨 100%, 기준 360×800dp에서 처음 5행을 목표로 하되 작은 화면/200% 글씨에서는 읽기·스크롤·고정 action 접근성을 우선한다. 5개를 맞추려고 글씨/터치 영역을 줄이지 않는다.
- `TaskSheet`, `TimerView`, `LedgerRow`, `ChoiceChips`, `PlanActualDelta`, `MetricHero`, `FixedActionBar`는 실제 구현 후 공용 API와 변형을 문서화한다. 재사용되지 않는 과도한 디자인 시스템은 만들지 않는다.

## 구현 전 디자인 검수 산출물

P5에서는 실제 기준 기기의 밝은/어두운 모드에서 다음을 증빙한다: 첫 실행 빈 목록, 5개/30개 목록, 시트 닫힌 뒤 명확한 재열기 버튼, 실행 중 화면, 200% 글씨, 키보드 열린 수동 입력, 날짜별 원장. 레퍼런스 화면과 구현 스크린샷을 구분하고 URL·열람일·관찰/추론·채택/배제 이유를 함께 기록한다.

매 편집마다 유료 사이트 3개를 다시 조회하지 않는다. 패턴을 바꿀 때만 기존 근거를 재확인하고 이 결정표를 갱신한다. 사용자 실제 기록을 외부 디자인 도구에 보내지 않는다.

## P5 구현 부품

2026-09-06 P5 구현은 아래의 작은 의미 부품을 사용한다. 모두 `mobile/src/` 내부 부품이며 DB·Auth·API를 직접 가져오지 않는다.

| 부품 | 역할 / 변형 |
|---|---|
| `TaskSheet` | 오늘 항목을 유형별 행동 텍스트와 함께 표시하고, 고정 `할일 추가`·`직접 기록` action을 제공한다. 목록·추가·수동 선택은 한 sheet overlay 안에서 교체한다. |
| `TimerView` | P5의 `경과 시간`과 `정지`, 할일 시트 재열기만 보인다. 목표·남은·초과·일시정지는 P6 전까지 노출하지 않는다. |
| `LedgerRow` | 항목명·값·출처/메모를 한 행에 보이고, 편집 가능한 행만 press action을 받는다. |
| `ChoiceChips` | 적은 수의 상호 배타 선택(시간 칩·항목 유형)에 사용한다. 긴 데이터 목록이나 내비게이션을 제한하지 않는다. |
| `PlanActualDelta` / `MetricHero` | 기록의 계획·실제·차이 3열과 오늘 가용시간을 숫자로 표시한다. 과거에 보존되지 않은 계획은 `미보존`으로 표시한다. |
| `FixedActionBar` | sheet footer 또는 기록의 직접 기록·오늘 종료처럼 화면 하단 행동을 묶는다. |
