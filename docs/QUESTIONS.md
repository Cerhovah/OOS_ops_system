### Q-009 — Phase 3 음성 전사와 자유 문장 AI fallback 제공자

- 날짜: 2026-09-03
- 상태: OPEN
- 관련 명세: §9.1 음성 메시지·자유 문장, §10.4 비용·외부 자격증명, AC-26
- 멈춘 단계/작업: 실제 음성 전사와 규칙 파서 실패 시 AI 구조화의 원격 게이트만 대기한다. 규칙 파서, 제안·확인 흐름, 제공자 중립 어댑터와 자동 테스트는 완료했다.
- 필요한 결정: OpenAI 호환 전사/구조화 API를 사용할지, 다른 제공자를 사용할지, Phase 4 제공자 결정과 함께 할지.
- 선택지와 영향: 지금 제공자를 고르면 AC-26 실서비스 검증까지 닫을 수 있다. Phase 4와 함께 고르면 Phase 3의 음성 실서비스 게이트만 사용자 승인 보류로 남는다.
- 에이전트 기본 제안: OpenAI 호환 HTTP 어댑터를 제공자 중립으로 구현하고 비밀값은 Supabase secret에만 둔다. 실제 유료 API 선택·키 등록 전에는 호출하지 않는다.
- 결정 전 임시 조치: 비용 없는 규칙 기반 자유 문장과 전체 확인 버튼 흐름을 구현·테스트했고, provider secret이 없으면 음성은 적용하지 않고 사실형 안내만 보낸다.

### Q-008 — Phase 3 Telegram bot token과 허용 chat_id

- 날짜: 2026-09-03
- 상태: OPEN
- 관련 명세: §5.8, §9.1, §10.4, §14, AC-23~AC-26
- 멈춘 단계/작업: 실제 Telegram 웹훅 연결과 실대화 게이트만 대기한다. 서버·앱 구현, migration/RLS, Edge Function v2 배포와 자동 검증은 완료했다.
- 필요한 결정: 사용자가 BotFather에서 발급한 bot token. 허용 chat_id는 사용자가 봇에 `/start`를 보낸 뒤 설정 스크립트가 자동 탐지한다.
- 선택지와 영향: 새 개인용 봇을 만들거나 기존 개인용 봇을 사용한다. 기존 봇에 다른 webhook이 있으면 교체되므로 새 봇이 안전하다.
- 에이전트 기본 제안: Phase 3 전용 새 봇을 만들고, token은 대화나 저장소에 붙이지 않고 로컬 보안 입력을 거쳐 Supabase secret으로 직접 등록한다.
- 결정 전 임시 조치: token 문자열을 코드·문서·앱 번들에 넣지 않는다. `supabase/scripts/configure-telegram.ps1`가 token을 숨김 입력으로 받아 secret·chat_id·Vault cron·webhook을 일괄 설정하도록 준비했다.

### Q-005 — 공개 배포·결제·운영 서버를 포함한 상용화 명세 확장

- 날짜: 2026-09-02
- 상태: OPEN
- 관련 명세: §3.2 Phase 1~5, §3.3 비목표, §10.4 비용·자격증명·제품 동작 정지 조건
- 멈춘 단계/작업: Phase 1 검증은 계속한다. 공개 스토어 제출, 결제 연동, 유료 인프라 생성·운영은 명세와 수용 기준이 승인될 때까지 시작하지 않는다.
- 필요한 결정: 우선 출시 플랫폼(Android만 또는 Android+iOS), 판매 대상(디지털 앱 기능/구독, 실물·외부 서비스 결제, 또는 결제 없음), 개인용에서 다중 사용자 서비스로 확장할지, 운영비·개발자 계정·결제 계정 사용 범위.
- 선택지와 영향:
  - Android 우선 상용화: 현재 Galaxy 실기기와 Google Play를 기준으로 production AAB, Play Billing(디지털 상품일 때), 서버 검증, 스토어 정책·운영을 먼저 완결한다.
  - Android+iOS 동시 상용화: Apple Developer/App Store/IAP·iOS 실기기 검증까지 병행해 범위와 계정·심사 비용이 늘어난다.
  - 개인용 production 배포 후 결제: 먼저 스토어 설치·서버 백업까지 안정화하고 결제·구독은 다음 게이트로 분리한다.
- 에이전트 기본 제안: Android 우선으로 `상용화 기반(운영 Supabase·보안·백업·production AAB·Play 비공개 테스트)`과 `결제/공개 출시`를 별도 게이트로 나눈다. 판매 대상이 디지털 앱 기능인지 먼저 확정한다.
- 결정 전 임시 조치: 현재 SPEC은 변경하지 않고 F-005에 후보 범위만 기록한다. Phase 1~4를 상용 출시 완료로 표현하지 않는다.
- 사용자 답변: 배포 및 결제를 바로 붙일 수 있는 완결 앱과 완전한 서버를 원한다는 목표를 2026-09-02 확인. 개발 중에는 내부 development APK를 사용하되, 최종적으로 APK를 직접 관리하지 않고 사용할 개인 앱, 쉬운 리팩터링, 빌드·스토어 배포·결제 확장을 염두에 둔 구조를 원함. 플랫폼·판매 대상·운영 범위 세부 선택은 대기 중.

### Q-006 — Phase 2 인증과 전체 초기화 범위

- 날짜: 2026-09-02
- 상태: SUPERSEDED
- 관련 명세: §8 인증 질문 영역, §5.8 전체 초기화, I-7 로컬 우선, I-8 데이터 소유권, §14 기본값
- 결정: §14 기본값인 이메일 OTP를 사용하고, `전체 초기화`는 이 기기 SQLite만 초기화해 원격 백업은 보존한다. 원격 전체 삭제는 현재 구현하지 않는다.
- 영향: OTP는 재설치 복구용 동일 사용자 ID와 RLS의 `auth.uid()`를 얻기 위한 무비밀번호 인증이다. 매직링크 딥링크는 추가하지 않으며 인증 방식은 UI/동기화 엔진과 분리한다.
- 사용자 답변: 2026-09-02 — 이메일 OTP 필요 이유를 질문하면서 기존 수기 검증을 승계하고 Phase 2를 즉시 시작하도록 지시했다. 별도 대안을 고르지 않았으므로 명세 기본값을 적용한다.
- 대체 관계: 인증 방식은 Q-007 이메일 매직링크가 대체한다. 기기 로컬 초기화 결정은 유지한다.
