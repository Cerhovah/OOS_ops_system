# QUESTIONS

사용자 결정 없이는 진행할 수 없는 현재 항목만 기록한다. §14에서 기본값이 정해진 항목은 기본값으로 계획하며, 실제 정지 조건이 되기 전에는 질문으로 올리지 않는다.

## 상태 표기

- `OPEN`: 답변 전이며 `멈춘 단계/작업`에 적힌 범위만 중지
- `ANSWERED`: 답변과 날짜를 기록하고 관련 계획·결정을 갱신
- `SUPERSEDED`: 후속 결정으로 대체

## 답변 완료

### Q-001 — Phase 1 실기기 검증 대상

- 날짜: 2026-08-20
- 상태: ANSWERED
- 관련 명세: §7, §10.3, §11 AC-1·AC-13·AC-14, §14
- 멈춘 단계/작업: 없음. Phase 1 Android 실기기 게이트 완료.
- 필요한 결정: Phase 1에서 실제 설치·알림·콜드 스타트 딥링크를 검증할 사용자 휴대폰의 OS, 기기 모델, OS 버전. iPhone만 사용할 경우 AC-14의 Android 개발 빌드 검증에 사용할 수 있는 Android 기기 또는 별도 검증 방법도 필요하다.
- 선택지와 영향:
  - Android 실기기: AC-1·AC-13·AC-14를 같은 기기에서 검증할 수 있다. 현재 기본 제안이다.
  - iPhone 실기기: AC-1·AC-13은 iPhone에서 검증하고, AC-14는 Android 개발 빌드에서 별도로 검증해야 한다.
  - 두 OS 실기기: 양쪽 설치·알림 경로를 검증할 수 있으나 수동 검증 범위가 늘어난다.
- 에이전트 기본 제안: 사용 가능한 Android 실기기를 Phase 1 주 검증 대상으로 지정하고, iOS는 개발 빌드 준비까지만 수행한다. 실제 보유 기기가 다르면 그 기기를 우선한다.
- 결정 전 임시 조치: Android를 Phase 1 주 검증 대상으로 사용하고 iOS 검증·Phase 2 착수는 하지 않는다.
- 사용자 답변: 2026-08-23 Android development APK 설치, 아이콘 실행, Metro tunnel 연결과 Android bundle 수신을 확인했다. 2026-08-24 잠금화면 알림과 비행기 모드 검증까지 완료했다. 기기 모델·Android 버전은 미기록이나 Phase 1 판정을 막지 않는다.

### Q-002 — Phase 2 Supabase 프로젝트

- 날짜: 2026-08-24
- 상태: ANSWERED
- 관련 명세: §8, §11 AC-19~AC-22, §14
- 멈춘 단계/작업: 없음. Phase 2 구현은 별도 착수 명령 전까지 시작하지 않는다.
- 필요한 결정: 기존 또는 신규 프로젝트, 리전, 플랜.

- 사용자 답변: 전용 신규 Supabase 프로젝트를 만들고, 선택 가능하면 Northeast Asia (Seoul), 무료 플랜으로 시작한다.

- 상태: ANSWERED
- 관련 명세: §8, §11 AC-19·22, §14

### Q-004 — Phase 2 최초 동기화 원본

- 날짜: 2026-08-24
- 상태: ANSWERED
- 관련 명세: I-7·I-8, §8, §11 AC-19
- 멈춘 단계/작업: 없음. 실제 업로드 전에는 원본을 변경하지 않는다.
- 필요한 결정: 로컬 SQLite와 비어 있는 Supabase 중 최초 진실 원천.
- 선택지와 영향: 휴대폰 SQLite를 원본으로 정하면 현재 기록·삭제 묘비·계획 전 버전을 보존한 채 빈 원격 DB를 초기화할 수 있다.
- 에이전트 기본 제안: SQLite 전체를 검증 가능한 1회 초기 업로드로 전송하고 행 수·ID·버전을 대조한다.
- 결정 전 임시 조치: 업로드·병합·초기화하지 않는다.
- 사용자 답변: 현재 휴대폰 SQLite를 최초 원본으로 삼아 빈 Supabase에 전체 데이터·삭제 tombstone·계획 버전을 업로드한다.

### Q-005 — Phase 2 충돌 정책

- 날짜: 2026-08-24
- 상태: ANSWERED
- 관련 명세: I-7·I-8, §8, §11 AC-20·21
- 멈춘 단계/작업: 없음. 상세 스키마와 RPC는 Phase 2 착수 후 자동 테스트부터 설계한다.
- 필요한 결정: 충돌 승자와 감사 로그 보존 범위.
- 선택지와 영향: LWW는 자동 병합이 단순하지만 조용한 덮어쓰기를 막기 위해 모든 충돌의 양쪽 값을 보존해야 한다.
- 에이전트 기본 제안: 서버가 부여하는 동기화 버전·시각을 우선하고, 동률은 기기 ID와 변경 ID로 결정적으로 해소한다.
- 결정 전 임시 조치: 동기화 코드를 추가하지 않는다.
- 사용자 답변: LWW와 모든 충돌 로그 보존에 동의한다. 기기 시각만 믿지 않고 서버 시각 또는 동기화 버전과 결정적 동률 해소 규칙을 사용한다.
