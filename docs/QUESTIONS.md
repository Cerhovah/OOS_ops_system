# QUESTIONS

사용자 결정과 남은 선택의 이력을 기록한다. 최신 SPEC의 기본값으로 진행 가능한 작업은 계속하고, 실제 정지 조건이 있는 범위만 멈춘다. 권장안은 사용자 확정 답변과 구분한다.

## 상태 표기

- `OPEN`: 답변 전이며 `멈춘 단계/작업`에 적힌 범위만 중지
- `ANSWERED`: 답변과 날짜를 기록하고 관련 계획·결정을 갱신
- `SUPERSEDED`: 후속 결정으로 대체

### Q-016 — 첫 공개 버전의 계정·클라우드 범위

- 날짜: 2026-09-06
- 상태: ANSWERED

- 영향: public-cloud는 이번 범위에서 제외한다. P7에서 공개용 별도 application ID·capability·환경을 만들고, P8에서 사용자 공개 지시가 있을 때만 배포한다.

### Q-013 — hosted Auth 신규 가입 차단 적용 확인

- 날짜: 2026-09-04
- 상태: OPEN
- 관련 명세: 단일 사용자 범위, I-7, I-8, AC-22, AC-33, AC-35
- 멈춘 단계/작업: 로컬 리팩터와 테스트는 계속할 수 있다. Supabase Dashboard의 `Allow new users to sign up`을 끄고 저장하는 원격 계정 설정 변경만 사용자 확인 전까지 중지한다.
- 필요한 결정: 기존 사용자와 세션은 유지하고 새 Auth 사용자 생성만 hosted project에서 차단할지 확인.
- 선택지와 영향:
  - 신규 가입 차단: 현재 단일 소유자 Edge/RLS 모델과 일치하고 새 외부 계정 생성을 막는다. 기존 로그인·매직링크는 유지된다.
  - 현재 스위치 유지: 향후 계정을 만들 수 있지만 단일 소유자 AI 함수에는 접근할 수 없고 공개 운영 정책과 불일치한다.
- 에이전트 기본 제안: 기존 계정을 유지한 채 신규 가입만 차단하고, public Auth settings로 결과를 재확인한다.
- 결정 전 임시 조치: 앱은 `shouldCreateUser:false`, 저장소 `supabase/config.toml`은 `enable_signup=false`, AI 함수는 `OOS_OWNER_USER_ID` 일치만 허용한다. hosted Dashboard 값은 변경하지 않는다.

### Q-012 — 공개 운영 전 AI 호출 비용 한도

- 날짜: 2026-09-04
- 상태: OPEN
- 관련 명세: §9.1, §10.4, §21, AC-27~AC-30, Q-015~Q-016
- 2026-09-06 보완: 80,000원은 Mobbin·Figma·관련 MCP 레퍼런스 예산으로만 쓴다. 개인용 AI 비용은 이 예산에 포함하지 않으며, 실제 비용이 필요하면 별도 근거·금액·승인을 먼저 받는다. public-local에는 공개 AI를 제공하지 않는다.
- 멈춘 단계/작업: 현재 단일 소유자의 수동 분석과 Phase 4 리팩터는 계속할 수 있다. 백그라운드 자동 분석, 다중 사용자 공개 운영, 결제 연동은 서버 호출량 한도를 정할 때까지 시작하지 않는다.
- 필요한 결정: 사용자별 분당·일일 분석 횟수, 월간 OpenAI 프로젝트 예산, 한도 도달 시 차단 문구, 실패 요청의 재시도·중복 과금 정책.
- 선택지와 영향:
  - 보수적 개인용 한도: 사용량과 오작동 비용을 작게 제한하지만 짧은 시간에 여러 비교 분석을 하기 어렵다.
  - 넓은 개인용 한도: 현재 사용성은 좋지만 탈취된 세션이나 반복 요청의 비용 상한이 커진다.
  - 유료 사용자별 quota: 결제·권한·서버 원장까지 함께 설계해야 하므로 Q-005 상용화 게이트에 포함한다.
- 에이전트 기본 제안: Phase 4S 개인용 standalone에서 분당·일일 서버 quota와 OpenAI 프로젝트 월 예산을 함께 두고, 동일 요청 idempotency를 구현한다.
- 결정 전 임시 조치: Edge Function은 owner JWT, 요청·snapshot 바이트 상한, `store:false`를 강제한다. 자동 호출은 만들지 않고 사용자가 누른 1회 요청만 허용한다.

### Q-011 — 다중 기기 자연키 충돌 정책

- 날짜: 2026-09-04
- 상태: OPEN
- 관련 명세: I-7, I-8, AC-19~AC-22, Q-005
- 멈춘 단계/작업: 현재 한 기기의 개인용 앱과 백업 동기화는 계속할 수 있다. 두 기기에서 같은 주·날짜 데이터를 동시에 새로 만드는 정식 다중 기기 지원은 식별·병합 정책을 확정할 때까지 완료로 판정하지 않는다.
- 필요한 결정: `weekly_plans(week_start,version)`, 하루 메모·종료, 주간 코멘트, 오늘 수동 항목처럼 UUID와 별도 자연키 UNIQUE를 함께 쓰는 행을 충돌 시 합칠지, 한쪽을 최종값으로 선택할지, 사용자에게 병합 화면을 제공할지.
- 선택지와 영향:
  - 단일 작성 기기 유지: 가장 단순하고 현재 개인용 사용에는 충분하지만 다른 기기는 복구·열람 중심으로 제한한다.
  - 결정적 ID·자동 병합: 일반 사용은 간단하지만 기존 UUID 이관과 각 데이터 유형별 의미 규칙이 필요하다.
  - 충돌 확인 UI: 데이터 보존은 가장 명확하지만 동기화 UI와 테스트 범위가 커진다.
- 에이전트 기본 제안: 우선 Phase 4S 개인용 standalone은 단일 작성 기기로 명시하고, 다중 기기 공개 전 데이터 유형별 결정적 ID/병합 migration을 별도 AC로 구현한다.
- 결정 전 임시 조치: 기존 UUID와 데이터는 바꾸지 않는다. 이번 리팩터는 전송 중 최신 수정 보존, 기기-사용자 owner 고정, 미지원 원격 schema 중단까지만 적용한다. 현재 timestamp+offset pull은 단일 작성 기기에서만 사용하고, 다기기 작성 전에는 `(server_updated_at,table_name,local_id)` keyset과 실행 상한을 가진 owner RPC로 교체한다.

### Q-005 — 공개 배포·결제·운영 서버를 포함한 상용화 명세 확장

- 날짜: 2026-09-02
- 상태: SUPERSEDED
- 2026-09-06 대체: 사용자 최신 지시로 P5 UI/UX, P6 핵심 기능, P7 배포 준비, P8 공개 배포·유지보수 명세를 확정했다. Android 우선·결제 제외·총액 80,000원 계획이며 공개 계정 범위만 Q-016으로 분리한다. 아래 문단은 과거 질문 기록으로, 공개 배포 자체를 계속 비목표로 취급하지 않는다.
- 관련 명세: §3.2 Phase 1~5와 Phase 4R·4S, §3.3 비목표, §10.4 비용·자격증명·제품 동작 정지 조건
- 멈춘 단계/작업: Phase 4R 리팩터와 Phase 4S Android 개인용 standalone은 사용자 최신 지시로 계속할 수 있다. 공개 스토어 제출, 결제 연동, 다중 사용자화, 유료 인프라 생성·운영만 별도 수용 기준이 승인될 때까지 시작하지 않는다.
- 필요한 결정: 우선 출시 플랫폼(Android만 또는 Android+iOS), 판매 대상(디지털 앱 기능/구독, 실물·외부 서비스 결제, 또는 결제 없음), 개인용에서 다중 사용자 서비스로 확장할지, 운영비·개발자 계정·결제 계정 사용 범위.
- 선택지와 영향:
  - Android 우선 상용화: 현재 Galaxy 실기기와 Google Play를 기준으로 production AAB, Play Billing(디지털 상품일 때), 서버 검증, 스토어 정책·운영을 먼저 완결한다.
  - Android+iOS 동시 상용화: Apple Developer/App Store/IAP·iOS 실기기 검증까지 병행해 범위와 계정·심사 비용이 늘어난다.
  - 개인용 standalone 후 결제: 먼저 PC·Metro 없는 개인 설치와 서버 백업까지 안정화하고 스토어·결제·구독은 다음 게이트로 분리한다.
- 에이전트 기본 제안: Phase 4R 뒤 Android 개인용 standalone을 먼저 완결하고, 그 다음 `상용화 기반(운영 Supabase·보안·백업·production AAB·Play 비공개 테스트)`과 `결제/공개 출시`를 별도 게이트로 나눈다. 판매 대상이 디지털 앱 기능인지 먼저 확정한다.
- 결정 전 임시 조치: SPEC v0.3.0에는 사용자가 명시한 Phase 4R·4S까지만 추가했다. 공개 스토어·결제·다중 사용자 운영은 F-005 후보로 유지하며 Phase 1~4S를 상용 출시 완료로 표현하지 않는다.
- 사용자 답변: 배포 및 결제를 바로 붙일 수 있는 완결 앱과 완전한 서버를 원한다는 목표를 2026-09-02 확인. 2026-09-04에는 PC 없이 자체 구동하는 앱 개발 전에 Phase 4 전체를 재현성·독립성·간결성 중심으로 리팩터링하라고 순서를 확정했다. 따라서 Phase 4R → Android 개인용 Phase 4S까지는 진행하고, 공개 플랫폼·판매 대상·다중 사용자 운영 범위의 세부 선택은 계속 대기한다.
