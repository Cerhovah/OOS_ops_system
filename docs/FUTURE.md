# FUTURE

현재 Phase의 범위를 넓히지 않기 위해 후순위 아이디어를 보관한다. 등록은 구현 승인이 아니다. 2026-09-06 SPEC v0.5.0의 Phase 5~8은 이미 구체화되어 있으므로 이 목록을 Phase 5 기능 묶음으로 자동 편입하지 않는다.

## 후보

### F-001 — 웹 대시보드

- 제안 근거: SPEC §3.1 K
- 사용자 문제: 휴대폰 밖에서 장기 집계와 계획을 넓은 화면으로 보고 편집할 필요
- 기대 효과: 데스크톱 분석·계획 편집 인터페이스
- 비용/위험: 다기기 동기화·인증·충돌 처리가 먼저 안정화되어야 함
- 선행 조건: Phase 2 게이트 통과
- 검토 Phase: Phase 8 이후, 별도 요청 시

### F-002 — GitHub 등 외부 데이터 연동

- 제안 근거: SPEC §3.1 K
- 사용자 문제: 프로젝트 성과 기록의 수동 입력 비용
- 기대 효과: 검증된 외부 지표를 프로젝트 KPI에 연결
- 비용/위험: 외부 API 권한, 비용, 데이터 의미·중복 처리
- 선행 조건: 연결할 데이터·권한 범위와 수용 기준에 대한 사용자 승인
- 검토 Phase: Phase 8 이후, 별도 요청 시

### F-003 — 추가 웨어러블·건강 데이터 소스

- 제안 근거: 기존 저장소 후보
- 사용자 문제: 수면·운동·수치 데이터를 수동으로 옮기는 비용
- 기대 효과: 선택한 원자료의 기록 자동화

- 선행 조건: 대상 데이터 소스와 저장 범위에 대한 사용자 승인
- 검토 Phase: Phase 8 이후, 별도 요청 시

### F-004 — 자동화 규칙과 분석 시나리오 확장

- 제안 근거: 기존 저장소 후보
- 사용자 문제: 반복 기록·분석 설정 비용
- 기대 효과: 사용자가 명시적으로 정한 규칙의 반복 실행
- 비용/위험: 사용자 주권과 AI 적용 승인 원칙을 침해하지 않도록 별도 설계 필요
- 선행 조건: Phase 4 게이트 통과와 사용자 승인
- 검토 Phase: Phase 8 이후, 별도 요청 시

### F-005 — 공개 배포 승격 이력과 남은 결제 후보

- 2026-09-06 상태: **부분 승격**. 공개 Android 배포·배포 준비·백업/복구·운영 리팩터는 SPEC §19~§21로 이동했다. 과거의 공개 배포 비목표는 더 이상 유효하지 않다.
- 남은 후보: 결제·구독·구매 서버 검증·환불·유료 다중 사용자 운영·iOS 공개 배포. 이번 P5~P8 명세의 구현 범위가 아니다.
- 공개 계정/동기화 범위는 Q-016과 SPEC §19.1의 조건으로 다루며 결제와 자동으로 결합하지 않는다. 아래 내용은 최초 제안의 역사적 맥락이다.

- 제안 근거/제안일: 사용자 명시 목표, 2026-09-02. SPEC v0.3.0의 Phase 4S 개인용 standalone 이후에도 §3.3의 앱 스토어 공개 배포·결제·다중 사용자 운영 비목표를 변경해야 함.
- 사용자 문제: Phase 4S 개인 설치용 standalone을 넘어 스토어에서 설치·갱신하고 결제와 운영 서버를 실제로 사용할 수 있는 완결 제품 필요
- 기대 효과: production 앱 바이너리·스토어 출시·구매 검증·운영 백엔드·백업·모니터링을 하나의 출시 기준으로 검증
- 비용/위험: Google/Apple 개발자 계정, 결제 사업자·세금·약관·개인정보 처리, 서버 비용과 비밀값, 구매 검증·환불·구독 상태·장애 대응, 심사 정책이 포함됨
- 선행 조건: Phase 4R·4S 게이트, Q-005의 플랫폼·판매 대상·사용자 범위 승인, 운영 서버 환경 설계, 별도 AC/TESTPLAN과 비용 승인
- 검토 Phase: 공개 배포 부분은 Phase 7~8로 확정. 결제 등 나머지는 Phase 8 이후 별도 요구/예산/AC로 검토

## 비목표와의 구분

현재 비목표는 SPEC §3.3을 따른다. 공개 Android 배포는 승인된 계획 범위이며, 계정/서버 제공은 §19.1의 선택 분기를 따른다. 결제·소셜·게임화·광고·원격 텔레메트리는 추가하지 않는다. 과거 후보 등록은 사용자 최신 목표와 불변조건을 대체하지 않는다.
