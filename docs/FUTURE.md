# FUTURE

현재 Phase의 범위를 넓히지 않기 위해 명세에 포함된 후순위 또는 새 아이디어를 보관한다. 등록은 구현 승인이 아니며, Phase 5 착수 전에 사용자가 범위와 수용 기준을 별도로 승인해야 한다.

## 후보

### F-001 — 웹 대시보드

- 제안 근거: SPEC §3.1 L
- 사용자 문제: 휴대폰 밖에서 장기 집계와 계획을 넓은 화면으로 보고 편집할 필요
- 기대 효과: 데스크톱 분석·계획 편집 인터페이스
- 비용/위험: 다기기 동기화·인증·충돌 처리가 먼저 안정화되어야 함
- 선행 조건: Phase 2 게이트 통과
- 검토 Phase: Phase 5

### F-002 — GitHub 등 외부 데이터 연동

- 제안 근거: SPEC §3.1 L
- 사용자 문제: 프로젝트 성과 기록의 수동 입력 비용
- 기대 효과: 검증된 외부 지표를 프로젝트 KPI에 연결
- 비용/위험: 외부 API 권한, 비용, 데이터 의미·중복 처리
- 선행 조건: 연결할 데이터·권한 범위와 수용 기준에 대한 사용자 승인
- 검토 Phase: Phase 5

### F-003 — 추가 웨어러블·건강 데이터 소스

- 제안 근거: 기존 저장소 후보
- 사용자 문제: 수면·운동·수치 데이터를 수동으로 옮기는 비용
- 기대 효과: 선택한 원자료의 기록 자동화
- 비용/위험: 플랫폼 권한, 민감 데이터, 공급자 종속, 제품 범위 확대
- 선행 조건: 대상 데이터 소스와 저장 범위에 대한 사용자 승인
- 검토 Phase: Phase 5

### F-004 — 자동화 규칙과 분석 시나리오 확장

- 제안 근거: 기존 저장소 후보
- 사용자 문제: 반복 기록·분석 설정 비용
- 기대 효과: 사용자가 명시적으로 정한 규칙의 반복 실행
- 비용/위험: 사용자 주권과 AI 적용 승인 원칙을 침해하지 않도록 별도 설계 필요
- 선행 조건: Phase 4 게이트 통과와 사용자 승인
- 검토 Phase: Phase 5

## 비목표와의 구분

SPEC §3.3의 다중 사용자·소셜·게임화·광고·원격 텔레메트리·앱 스토어 공개 배포 준비는 현재 명세의 비목표이며 자동으로 FUTURE 후보가 되지 않는다. 추가하려면 사용자가 명세 범위를 명시적으로 변경해야 한다.
