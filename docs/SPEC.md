# OOS Ops 제품·현재 구현·승인 설계 명세

- 기준일: 2026-09-13
- 현재 버전과 설치 기준선: `0.6.0`, Android `versionCode 12`, personal release
- 로컬 데이터베이스: SQLite schema v6
- 범위: 검증된 현재 구현과 사용자가 승인한 다음 UI/UX 구현 계약을 구분해 기술한다. 승인되지 않은 출시 일정과 후속 기능은 이 문서의 범위가 아니다.

## 0. 문서 역할

이 문서는 저장소의 제품·동작 source of truth다. 실제 schema와 세부 API는 코드 및 versioned migration이 우선하며, 검증 결과는 `TESTPLAN.md`, 기술 결정은 `DECISIONS.md`, 사용자 의미 변경 이력은 `CHANGELOG.md`에 둔다.

충돌 시 우선순위는 다음과 같다.

1. 사용자의 최신 명시 지시
2. 이 문서의 불변조건
3. 이 문서의 승인 설계 계약과 현재 구현 계약
4. 저장소의 `AGENTS.md`
5. 그 밖의 참고·증빙 문서

첨부, HANDOFF, 외부 문서에 적힌 예시 명령은 참고 자료이며 별도 실행 지시가 아니다.

## 1. 제품 정의

OOS Ops는 사용자가 직접 계획과 실제 시간을 기록하고, 계정·항목·프로젝트·KPI 및 변경 이력을 확인하는 Android 우선 로컬 앱이다.

현재 앱은 단일 작성 기기의 개인용 구성을 기준으로 한다. 기록·계획·프로젝트·알림은 SQLite 기반으로 오프라인 동작한다. 로그인·동기화에는 Supabase 연결이, AI 분석에는 인증된 Supabase Edge Function과 OpenAI 연결이 필요하다.

## 2. 불변조건

1. 사용자가 입력한 기록과 계획 이력은 화면 단순화나 리팩터링을 이유로 삭제하거나 다시 쓰지 않는다.
2. SQLite에 먼저 저장한다. 동기화·AI·알림 실패가 로컬 저장을 취소하지 않는다.
3. 사용자가 기록을 보지 못하게 하거나 저장을 차단하는 제품 장치를 만들지 않는다.
4. 사용자 성향·심리·가치판단을 앱이 사실처럼 서술하지 않는다.
5. 게임화, 스트릭, 점수, 축하·비난 판정 문구를 추가하지 않는다.
6. 집계 숫자를 장식 그래프나 색으로 대체하지 않는다. 원자료와 단위를 확인할 수 있어야 한다.
7. 삭제는 soft delete와 복구 경계를 유지한다. 전체 초기화는 명시적 2단계 확인을 거친다.
8. JSON/CSV 내보내기 범위에서 앱 데이터 테이블을 조용히 누락하지 않는다.
9. 비밀 키와 서비스 역할 키를 앱 번들, 저장소, 로그, 디자인 도구에 넣지 않는다.
10. migration은 새 versioned script로만 상향하며 과거 migration을 수정하거나 파괴적으로 초기화하지 않는다.
11. TypeScript strict를 유지하고 `any`를 사용하지 않는다.
12. 원격 동작과 UI는 repository·domain 경계를 우회해 SQLite를 직접 조작하지 않는다.
13. Mobbin/Figma에는 합성 데이터만 사용하고, 상용 앱의 브랜드·문구·화면을 그대로 복제하지 않는다.
14. 반복 횟수·기간·고정 성능 수치를 기능 완료 조건으로 두지 않는다. 변경 위험에 맞는 최소 검증을 우선한다.

## 3. 현재 전달 범위

### 3.1 내비게이션

- 하단 탭은 `오늘`, `기록` 두 개다.
- 나머지 기능은 기록 화면의 `더보기`에서 진입한다.
- 더보기는 설정 기반 route 목록을 사용하며 `기능`, `관리`, `시스템` 그룹으로 렌더링한다.
- 현재 진입점은 지표, 주간 시간 분배, 프로젝트, AI 분석, 시간과 알림, 항목 관리, 계정 관리, 기록 관리, 설정이다.
- 각 기능은 고유 route와 화면 소유권을 가진다. 설정에는 동기화와 백업, 데이터 내보내기, 앱 초기화, 앱 정보만 남긴다.

### 3.2 오늘

#### 3.2.1 현재 구현

- 앱을 열면 현재 날짜와 오늘 실제/남은 계획 다음에 계정→항목 오늘 목록을 바로 보여준다.
- 항목 행은 현재 실제, 계획 기준 남은 시간과 실행 상태를 표시하고, 행을 누르면 action sheet에서 타이머 시작 또는 직접 기록을 고른다.
- 동시에 흐르는 타이머는 하나다. 실행 중에는 일시정지·종료, 일시정지 중에는 다시 시작·종료를 제공하며 다른 항목 전환은 기존 실행을 일시정지한 뒤 명시적으로 시작한다.
- 실행·일시정지 상태는 로컬 `timer_runtime:{entryId}` 설정으로 앱 재시작 뒤 복원하고, 종료 시 기존 SQLite entry와 같은 transaction에서 정리한다.
- 화면 갱신 tick은 전체 snapshot 새로고침이나 DB 쓰기를 유발하지 않는다. 타이머 자동 종료와 active/paused 상태의 서버 동기화는 아직 없다.

#### 3.2.2 구현·검증된 P5 재설계 계약

- 앱을 열면 별도 진입 버튼이나 빈 실행 placeholder 없이 오늘 목록을 첫 화면에 즉시 보여준다.
- 상단에는 현재 날짜, 오늘 실제 시간, 오늘 계획의 남은 시간을 간결하게 표시한다.
- 계획된 계정은 기본 펼침 상태로 두고 계정→항목 위계를 유지한다. 계획되지 않은 항목은 `다른 항목 기록하기`에서 불러온다.
- 각 시간형 항목 행은 항목명, 오늘 실제, 남은 시간 또는 계획 대비 signed 차이, 현재 상태를 한눈에 보여준다. 목표를 넘겨도 경고색이나 판정 문구를 쓰지 않고 `계획 대비 +15분`처럼 표시한다.
- 항목 행을 누르면 즉시 시작하지 않고 간결한 action sheet를 연다. 1차 행동은 `시작`, 보조 행동은 `직접 기록`이다.
- 동시에 시간이 흐르는 타이머는 하나다. 다른 항목을 시작하려 할 때 현재 타이머를 조용히 종료하지 않고 `현재 실행으로 돌아가기` 또는 `현재 실행을 일시정지하고 새로 시작`을 명시적으로 선택하게 한다. 일시정지된 기존 세션은 해당 항목에서 다시 시작하거나 종료할 수 있게 남긴다.
- 실행 중 카드는 계정·항목 맥락, 초 단위 경과 시간, 계획 기준 남은 시간 또는 signed 초과 시간을 보여주고 `일시정지`, `종료하고 기록`을 제공한다.
- 일시정지 상태에서는 경과 시간이 증가하지 않으며 `다시 시작`, `종료하고 기록`을 제공한다.
- 계획 시간을 채우지 못해도 언제든 종료할 수 있다. 종료는 기존 반올림 규칙으로 정수 분 기록을 SQLite에 먼저 저장하고 오늘 합계·항목 행·기록 원장에 즉시 반영한다. 30초 미만 기록이 0분이 되더라도 저장을 차단하거나 임의로 1분으로 올리지 않는다.
- 타이머 실행 중에도 직접 기록은 허용하되, 현재 타이머가 계속 측정 중임을 중립적으로 알린다.
- 앱 재시작과 foreground 복귀에서는 로컬에 저장한 실행 상태, 시작 시각, 누적 일시정지 시간을 기준으로 같은 상태를 복원한다.
- 실행 화면은 독립 전체 화면으로 사용자를 가두지 않는다. 첫 화면 목록과 현재 실행 카드가 함께 핵심 루프를 이룬다.

#### 3.2.3 P5/P6 기능 경계

- P5는 Today-first 화면, 로컬 단일 타이머 상태, 일시정지·재개·언제든 종료, 로컬 복원과 기록 반영까지만 소유한다.
- P5 UI 변경만으로 SQLite schema, sync payload, Supabase RPC/RLS, 서버 동기화 의미를 바꾸지 않는다.
- 여러 기기에서 실행·일시정지 상태를 동기화하거나 active timer의 conflict/revision 계약을 바꾸는 작업은 P6다.
- P6 동기화 계약을 시작하기 전 필요한 server migration, RPC/payload 호환, 구버전 client 처리와 배포 순서를 사용자에게 먼저 알리고 승인을 받는다.

### 3.3 기록

- 날짜별 실제 기록 원장을 제공한다.
- 항목별 행, 계정별 소계, 날짜 합계를 구분한다.
- 원본 계획이 보존되지 않은 과거 날짜는 계획을 재구성하지 않고 `계획 미보존`, 차이 `—`를 표시한다.
- 화면 시간은 한국어 `분`·`시간`으로 표시한다. 저장과 집계는 정수 분을 사용한다.
- 기록의 편집·삭제·복구는 기존 repository 의미를 유지한다.

### 3.4 지표

- 달력은 현재 날짜와 선택 날짜를 연결한다.
- 날짜 선택 시 그 날짜 한 건의 기록 상세를 표시한다.
- `주간보기`에서 선택 주의 계정·항목 집계를 표시한다.
- `이전 주`, `이번 주`, `다음 주` 이동을 유지하며 선택 날짜와 연동한다.
- `react-native-calendars@1.1314.0`을 앱 소유 adapter 뒤에서 사용한다.
- 2026년 공식 공휴일 이름은 offline release asset으로 표시한다. 범위 밖 날짜는 공휴일을 추정하지 않는다.
- Google/기기 캘린더 OAuth, 개인 일정 읽기·쓰기, runtime 공휴일 API는 포함하지 않는다.

### 3.5 주간 시간 분배

- 계정·항목별 주간 계획을 편집한다.
- 합계 168시간 검사를 표시하되 저장 자체를 차단하지 않는다.
- 계획 버전, 복원, 지난주 복사 등 기존 이력 의미를 보존한다.
- 입력 문자열은 공통 parser를 거쳐 정수 분으로 저장한다.

### 3.6 프로젝트와 KPI

- 프로젝트 상태, 실험, 판정일, KPI 정의와 KPI 기록을 관리한다.
- 프로젝트에 연결된 항목의 실제 투입시간을 파생해 보여준다.
- KPI는 사용자가 정의한 수치이며 앱이 성패나 사용자 성향을 판정하지 않는다.

### 3.7 알림

- 오늘 종료, 항목 일정, 기존 타이머 상한 알림을 지원한다.
- Android HIGH·PRIVATE 알림 채널과 콜드 스타트 딥링크를 유지한다.
- 알림 예약은 직렬화하며 DB commit 이후 조정한다. 알림 실패가 기록 저장을 되돌리지 않는다.

### 3.8 동기화와 인증

- 이메일 매직링크의 PKCE callback과 SecureStore 세션을 사용한다.
- SQLite outbox, foreground/online 자동 재시도, 수동 동기화, 마지막 동기화 시각, 충돌 로그를 제공한다.
- Supabase RLS와 최신 RPC allowlist 계약을 유지한다.
- 현재 schema·payload·서버 계약을 화면 변경만으로 수정하지 않는다.

### 3.9 AI 분석

- 감사, 패턴, 프로젝트, 최적화, 장기, 자유질문 여섯 모드를 제공한다.
- 완료된 최근 기간의 data package와 전송 snapshot을 확인할 수 있다.
- 세션 검색·soft delete·복구, 응답·사용량·비용 메타데이터를 보존한다.
- AI 제안은 사용자의 명시적 확인 뒤에만 새 계획 버전으로 적용한다.
- provider/model/API key는 서버에서 결정하며 production key를 앱에 넣지 않는다.

### 3.10 데이터 관리

- 계정, 항목, 프로젝트, KPI, 계획, 기록, 분석 이력을 관리한다.
- soft delete 및 복구, JSON/CSV 내보내기, 2단계 전체 초기화를 제공한다.
- 단일 앱 데이터 manifest에서 export/reset 범위를 파생하고 실제 schema와 exact-set 테스트를 유지한다.

## 4. 단위와 계산

- 영속 시간, 계획, 실제, 차이, 동기화, AI package, export의 기준 단위는 정수 분이다.
- 실행 중 화면은 초 단위로 표시할 수 있으나 영속 단위가 아니다. 경과 시간은 현재 시각, 저장된 시작 시각, 누적 일시정지 구간으로 계산한다.
- 종료 시 정수 분 변환은 `Math.round(milliseconds / 60_000)`과 0 하한을 사용하는 기존 규칙을 유지한다. UI와 repository가 서로 다른 반올림 규칙을 만들지 않는다.
- 주간 합계는 월요일 시작의 동일한 날짜 경계를 사용한다.
- 계획−실제 차이는 부호를 숨기지 않는다.
- 시간·날짜·집계 함수는 UI에서 분리하고 clock/now를 주입해 테스트한다.

## 5. UI와 접근성

- 화면은 safe-area inset과 글꼴 배율에 따라 하단 여백과 탭 높이를 계산한다. 특정 Galaxy 픽셀 상수를 사용하지 않는다.
- 하단 두 탭은 OOS가 소유하는 compact 2탭 구조다. 시스템 내비게이션과 시각적으로 분리하고 safe-area 위에 두되, 화면 폭을 차지하는 큰 floating widget이나 두꺼운 이중 바처럼 보이지 않게 한다. 정확한 표면·높이·offset은 승인 Figma와 기기 검수에서 정하고 특정 상용 앱의 탭을 복제하지 않는다.
- 주요 터치 대상은 최소 48dp를 기준으로 한다. 이는 hit area 규칙이며 보이는 아이콘·pill·버튼 높이를 48dp로 키우라는 뜻이 아니다. compact control은 전체 행 press target 또는 투명한 hitSlop으로 충족한다.
- 큰 글씨, TalkBack 의미, dark mode, 키보드, Android back, Reduce Motion 경계를 보존한다.
- 긴 계정·항목명과 숫자를 임의로 잘라 정보 손실을 만들지 않는다.
- `TaskSheet`, `TimerView`, `LedgerRow`, `ChoiceChips`, `PlanActualDelta`, `MetricHero`, `FixedActionBar` 등 의미 부품은 DB/Auth/API를 직접 가져오지 않는다.
- Light는 따뜻한 저채도 표면의 주 시각 승인안으로, Dark는 같은 의미 토큰을 사용한 별도 상태로 각각 설계·검수한다. 시스템 dark mode에서 우연히 렌더된 화면을 Light 승인안의 대체 증빙으로 사용하지 않는다.

## 6. 빌드와 환경

- Node.js `24.19.x`, npm `11.17.x`, Expo SDK `57`, React Native `0.86.3`, React `19.2.3`을 사용한다.
- npm과 `package-lock.json`만 사용하고 Expo CLI는 `npx expo`로 실행한다.
- 앱 코드는 `mobile/`, 서버 코드는 `supabase/`, 문서는 `docs/`에 둔다.
- 현재 일상 사용 기준은 서명된 `0.6.0(12)` personal release다. 기준 소스는 `3c7eb78`의 기능 구현과 그 자식 `7733ff6`의 Expo SDK 57 patch 정렬이며, SQLite schema와 Supabase/sync 계약은 바뀌지 않았다.
- ADB 자동화는 사용자가 연결·디버깅을 승인한 기기에서 이 앱의 설치·실행·로그·화면 확인에만 사용한다.

## 7. 디자인 근거와 구현 선행 게이트

- 아래 역할과 `P5 Visual v2` 범위는 2026-09-13 사용자가 승인한 Phase 0 디자인 계약이다. Figma 설계 근거로 사용할 수 있지만, implementation gate 전체가 통과하기 전에는 앱 코드와 개발 빌드의 구현 근거로 사용할 수 없다.
- 레퍼런스는 하나의 평균 스타일로 섞지 않고 역할을 고정한다.
  - 시각 기준: Mobbin의 [timespent `Creating a recurring plan`](https://mobbin.com/flows/4b25d929-de2b-4d37-a017-03c13d9f23fb)에서 표면 위계, 간격 밀도, 타이포 위계, 행 처리와 컨트롤의 시각 무게만 채택한다.
  - 상호작용 기준: [Tiimo `Completing a task`](https://mobbin.com/flows/5b4c73db-d619-4f47-a666-5663d1b65ce3)에서 오늘 목록이 첫 화면에 보이고 선택→실행→종료 뒤 같은 맥락으로 돌아오는 연속성만 채택한다. 2026-09-13 재조회된 [완료 보조 흐름](https://mobbin.com/flows/35e4e630-7681-4ad3-a704-9e4b1b3797e5)은 완료 뒤 같은 목록으로 돌아오는 동작만 교차 확인한다.
  - 보조 기준: [Equinox+ `Completed daily activities`](https://mobbin.com/flows/e5c30bf9-efe1-4346-a86e-fcecfbc35e4f)에서 기록의 날짜→그룹→상세 위계와 절제된 dark mode만 채택한다.
- timespent 화면 아래의 검은 띠는 Mobbin 표식이므로 디자인에 포함하지 않는다. 그 위의 흰색 분할 pill은 실제 앱 UI지만 OOS 2탭의 크기·위치·그림자를 그대로 복제하지 않는다. OOS 내비게이션은 안전영역, 현재 2탭 정보 구조와 첫 화면 밀도에 맞춘 독립 제품 규칙이다.
- 브랜드 색, 캐릭터, 카피, 화면 조합을 복제하지 않는다. OOS의 계정→항목, 숫자·단위 노출, 비판단 문구, 로컬 기록 원장을 우선한다.
- 색상은 따뜻한 무채색 Light 표면과 한 계열의 저채도 accent를 기본으로 한다. 실행 상태는 작은 표시·텍스트·얕은 tint로만 강조하며, 일시정지는 경고색이나 큰 색면이 아니라 상태 문구와 중립 표면으로 구분한다. Dark는 Equinox+의 절제를 참고하되 별도 토큰 모드로 검수한다.
- 화면마다 독립 카드 테두리를 반복하지 않는다. Today 항목은 계정별 그룹 표면 안의 compact row와 구분선으로 묶고, 현재 실행만 한 단계 올린다. 보이는 컨트롤을 키우지 않고도 48dp hit area, 긴 이름과 큰 글씨를 보존한다.
- 기존 Figma `P5 Quiet Routine`과 `P5 Approved · Foundations/Components/Screens`는 모두 비교용 legacy다. 후자는 편집 가능한 변수·컴포넌트를 포함하지만 잘린 계정 목록, 불완전한 컴포넌트 표본, 현재 계약과 다른 4탭과 낮은 시각 완성도로 인해 구현 source of truth 승인을 철회한다.
- 새 source of truth는 같은 파일의 별도 `P5 Visual v2` 페이지다. 핵심 승인 frame은 Today 기본, 항목 선택, running, paused, Records이며, 전환 충돌·실행 중 직접 기록·no-plan/over-plan·긴 이름/큰 글씨·Light/Dark를 edge variant로 함께 정의한다. 합성 데이터만 사용한다.
- 각 frame은 코드 착수 전 Figma design context와 screenshot을 함께 확인하고, 사용자 승인과 읽기 전용 시각 검수를 통과해야 한다. 구현 뒤에는 같은 상태의 기기 screenshot을 승인 Figma와 나란히 비교한다. 고정 유사도 수치 하나로 시각 합격을 대신하지 않는다.
- `design/p5-visual-v2.gate.json`의 implementation gate가 승인되기 전에는 P5 Visual v2 앱 코드와 개발 빌드를 시작하지 않는다. 자세한 절차와 현재 차이는 `design/P5_VISUAL_PIPELINE.md`와 `design-research.md`에 둔다.

## 8. 최소 검증 원칙

- 문서만 바꾸면 내부 링크와 `git diff --check`만 확인한다.
- 일반 UI 변경은 typecheck, lint, 변경 화면의 관련 테스트를 실행한다.
- 데이터·migration·동기화 계약 변경은 관련 저장·보존·client/server 계약 테스트를 추가한다.
- dependency, native, schema, sync 계약을 바꾸거나 큰 기능 묶음을 종료할 때만 전체 `npm run verify`를 실행한다.
- 작은 UI 수정마다 APK, 원격 DB, 전체 실기기 시나리오를 반복하지 않는다.
- 실기기 확인은 변경된 핵심 흐름을 한 번 확인하고 build/OS/기기와 실제 결과만 기록한다.
- 대규모 시각 변경은 Mobbin 역할표 → high-fidelity Figma → frame별 design context/screenshot → 읽기 전용 시각 검수 → 화면 단위 구현 → 합성 데이터 기기 비교 순서로 진행한다. Figma 승인 전에는 코드·APK 검증을 반복하지 않는다.
- screenshot 자동 비교는 환경·폰트·테마를 고정한 합성 데이터 테스트의 drift 탐지 보조수단이다. 개인용 실기기 데이터를 초기화하지 않으며 수치 일치만으로 UX·접근성 승인을 대체하지 않는다.
- 데이터 손실 가능성, 승인하지 않은 과금·공개, 불변조건 충돌이 생기면 해당 범위만 멈추고 사용자에게 구체적으로 보고한다.

## 9. 현재 검증 기준선

- Phase 1, 2, 4, 4R, 4S, 5의 완료 증빙을 보존한다.
- Phase 6-1 기능과 P5 Today-first 구현을 포함한 현재 소스는 TypeScript/ESLint, 40 files/238 tests, Supabase 계약 2 files/8 tests, Expo dependency check, Doctor 21/21, Android Hermes bundle을 통과했다.
- SM-S721N(Android 16)에서 더보기 분리, 지표 달력과 단일 날짜 상세, 주간보기, 계정→항목 불러오기, 기록 원장, 3-button navigation safe-area를 확인했다.
- Expo SDK 57이 요구한 13개 direct dependency를 호환 patch로 정렬한 뒤 clean `npm ci`와 전체 `npm run verify`를 통과했다. Android Hermes export는 1,832 modules와 4.8MB `.hbc`다.
- EAS personal `769d5e3e-6df8-49ae-9994-11458c7fe8a4`로 `0.6.0(12)` standalone을 만들고, DB/WAL/SHM 해시 일치 백업 뒤 SM-S721N(Android 16)에 데이터 보존 update install했다.
- Metro/ADB reverse 없는 cold start, Today 시작·일시정지·재시작 복원·재개·타이머 전환·직접 기록·종료·합계/원장 반영과 기존 수동 sync 전송 대기 0건을 확인했다.
- 이 기준선은 기능·데이터 보존의 증거다. 2026-09-13 현재 시각 방향의 공개 승인에는 사용하지 않으며, 새 `P5 Visual v2` 디자인과 구현·기기 비교가 끝날 때까지 현재 UI를 공개 가능 디자인으로 판정하지 않는다.
