# DECISIONS

기술적 자율 결정과 근거를 ADR로 기록한다. 제품 철학, §2 불변조건, 사용자 권한, 데이터 소유권, 승인된 범위는 이 문서로 변경할 수 없다.

## 기록 원칙

- 폴더 구조, 상태 관리, 보조 라이브러리, 테스트 도구, 인덱스, 성능·접근성 구현처럼 §0.3 자율 영역의 선택만 기록한다.
- 사용자 선호나 제품 동작을 바꾸는 결정은 ADR로 대신하지 않고 `QUESTIONS.md`에 올린다.
- 명세에 이미 확정된 Expo/React Native, Expo Router, expo-sqlite, 로컬 알림, append-only 계획, 소프트 삭제는 ADR의 신규 결정이 아니다.
- 대체된 결정도 삭제하지 않고 `대체` 상태와 후속 ADR 번호를 남긴다.

## 결정 목록

### ADR-001 — Android 하단 탭의 글자 배율·안전영역 대응

- 날짜: 2026-08-23
- 상태: 승인
- 맥락: Android 실기기에서 시스템 글자 배율이 큰 경우 하단 5개 탭 라벨이 시스템 탐색 영역과 겹쳤다. 기존 고정 `paddingBottom: 8`은 React Navigation이 계산한 bottom safe-area padding을 덮어썼다.
- 결정: `useWindowDimensions().fontScale`과 `useSafeAreaInsets().bottom`으로 탭 높이를 계산하고, 고정 bottom padding을 제거한다. `tabBarAllowFontScaling`은 유지한다.
- 대안: 탭 글자 배율을 끄기, 고정 높이·여백 늘리기.
- 근거: 글자 배율을 끄면 §10.6의 폰트 크기 설정 존중을 어기고, 고정값은 기기별 시스템 탐색 높이와 접근성 배율을 안정적으로 처리하지 못한다.
- 결과 및 위험: 큰 글자에서 탭 바가 높아져 본문 세로 공간은 줄지만 라벨과 시스템 버튼은 분리된다.
- 되돌림/재검토 조건: 실기기에서 과도한 탭 높이 또는 다른 Android 탐색 모드의 여백 문제가 확인될 때.
- 관련 불변조건/AC: I-9, §10.6, AC-1
- 대체 관계: 없음

### ADR-002 — Node 24 내장 SQLite를 이용한 repository 통합 검증

- 날짜: 2026-08-23
- 상태: 승인
- 맥락: 기존 자동 테스트는 시드 배열과 순수 함수만 검사해 실제 migration SQL, transaction, soft delete, append-only 계획, 전체 테이블 내보내기의 회귀를 잡지 못했다. 환경 복구가 끝난 상태이므로 새 패키지 설치도 피해야 했다.
- 결정: 테스트 전용 어댑터에서 Node 24의 `node:sqlite` 메모리 DB를 Expo SQLite의 비동기 인터페이스로 감싸고, 제품 repository와 migration 코드를 그대로 실행한다. 제품 런타임은 계속 `expo-sqlite`만 사용한다.
- 대안: 모든 repository 경로를 mock 처리, 별도 SQLite 테스트 패키지 설치, 실기기 수동 검증에만 의존.
- 근거: 실제 SQLite 제약과 SQL을 실행하면서 의존성·앱 번들·운영 DB를 변경하지 않는다. 테스트마다 메모리 DB를 새로 만들어 사용자 기기 데이터에는 접근하지 않는다.
- 결과 및 위험: Node 24 실행 환경이 필요하며 Expo SQLite와 Node SQLite의 드라이버 차이는 실기기 최종 점검으로 보완한다.
- 되돌림/재검토 조건: Expo SQLite가 Node 환경 공식 테스트 드라이버를 제공하거나 SQL 동작 차이가 발견될 때.
- 관련 불변조건/AC: I-7, AC-2, AC-4, AC-7, AC-10, AC-11, AC-12, AC-15
- 대체 관계: 없음

### ADR-003 — 반복 알림과 독립된 일회성 실기기 테스트 경로

- 날짜: 2026-08-23
- 상태: 승인
- 맥락: DAILY 시각을 수동 편집하는 검증에서 첫 알림은 수신했으나 상호작용을 완료하지 못했고, 시각을 다시 바꾼 두 번째 알림은 오지 않았다. 반복 예약 자체, 저장 시각, Android 표시, 사용자 탭을 한 번에 시험해 원인을 분리하기 어려웠다.
- 결정: 실제 DAILY 예약은 유지하고, 설정을 변경하지 않는 30초 TIME_INTERVAL 테스트 알림을 별도로 제공한다. 알림에는 `오늘 종료 열기` action과 `/today/close` 데이터를 함께 두고, 처리된 마지막 response는 즉시 지운다. 시각 설정은 버튼형 선택기로 바꾼다.
- 대안: DAILY 시각을 반복 변경하며 시험, 외부 알림 테스트 도구 도입, 새 native 시간 선택 패키지 설치.
- 근거: 실제 예약 상태를 오염시키지 않고 같은 날 반복 재현할 수 있으며, 현재 APK와 Expo SDK 57 API만 사용해 재빌드가 필요 없다.
- 결과 및 위험: 테스트 알림도 Android 시스템의 앱 알림 권한·채널 설정 영향을 받는다. 기존 Android 채널은 sound/importance 변경이 불가능해 HIGH·기본음·진동·PUBLIC 설정의 `daily-records-v2`를 새로 생성한다. 30초 안에 앱을 최근 앱에서 닫아야 하는 수동 절차는 남는다.
- 되돌림/재검토 조건: 실기기에서 TIME_INTERVAL 알림 또는 category action이 지원되지 않거나 OS별 동작 차이가 확인될 때.
- 관련 불변조건/AC: I-7, AC-13, AC-14
- 대체 관계: 없음

### ADR-004 — 서버 순서 기반 outbox LWW 동기화 계획

- 날짜: 2026-08-24
- 상태: 승인(Phase 2 구현 전 계획)
- 맥락: Phase 2는 로컬 우선 SQLite를 유지하면서 빈 Supabase로 현재 데이터를 최초 업로드하고, 이후 오프라인 변경을 자동 전송해야 한다. 기기 시각만 이용한 LWW는 시계 오차와 동일 시각 충돌에서 결과가 불안정하다.
- 결정: 자체 outbox와 tombstone을 사용한다. 서버가 수락한 변경에는 서버 동기화 버전과 서버 시각을 부여하고 이를 LWW의 주 순서로 사용한다. 동률은 `device_id`와 고유 `mutation_id`의 고정 정렬로 해소한다. 충돌 시 승자·패자의 값, 순서 키, 원인과 처리 결과를 모두 충돌 로그에 보존한다.
- 대안: 기기 `updated_at`만 사용하는 LWW, CRDT/외부 동기화 라이브러리, 충돌마다 사용자 수동 선택.
- 근거: 명세가 허용한 자체 outbox 방식이며, 오프라인 쓰기를 막지 않으면서 결과를 결정적으로 재현하고 조용한 덮어쓰기를 피할 수 있다.
- 결과 및 위험: 서버 버전 발급을 원자적으로 처리할 Postgres 함수·제약과 재시도 멱등성 키가 필요하다. 최초 업로드 전 전체 export와 원격 빈 상태를 검증하며, 행 수·ID·삭제 묘비·계획 버전 대조가 끝나기 전 로컬 원본을 삭제하거나 교체하지 않는다.
- 되돌림/재검토 조건: AC-20 다기기 충돌 시험에서 순서가 결정적이지 않거나, 외부 라이브러리가 동일한 보존·감사·오프라인 조건을 더 단순하게 충족한다고 검증될 때.
- 관련 불변조건/AC: I-7, I-8, AC-19, AC-20, AC-21, AC-22
- 대체 관계: 없음
